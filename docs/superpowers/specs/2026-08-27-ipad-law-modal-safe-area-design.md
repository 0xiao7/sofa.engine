# iPad 法條小窗與頂部安全區設計

## 目標

在選擇題解析中，所有可辨識的法規名稱與條號都可點擊，並在目前題目頁內開啟既有法條小窗；同時讓 iPad 網頁、加入主畫面與原生殼層的頂部導覽列都避開系統狀態列。

## 現況與根因

- 最新主線已有 `quiz-article-panel`，可在頁內載入完整條文、按叉關閉並保留原題。
- 解析連結辨識目前可處理完整的「法規名稱＋條號」，但「所得稅法第 34 條、第 51 條」這類省略第二次法規名稱的連續引用，後一個條號不一定會轉成連結。
- `sofa.css` 只在窄於 760px 或 `ios-reader-app` 類別下替 `.topbar` 加入 `safe-area-inset-top`。iPad 橫向與直向通常寬於 760px，因此截圖中的系統時間列會與導覽列共用頂部空間。

## 設計

### 法條引用

- 保留既有 `quiz-article-panel` 與 `openQuizArticlePanelByTarget()`，不另開分頁。
- 擴充 `linkifyLawRefs()`：同一句已辨識出法規名稱後，緊接的「、第 N 條」沿用同一法規名稱。
- 每個連結保留 `href` 作為無 JavaScript 備援，但正常點擊由頁面事件攔截並開啟小窗。
- 小窗可由右上角 ×、背景或 Escape 關閉；關閉後原題、答案與捲動位置不變。
- 無法可靠辨識法規名稱或條號時維持純文字，不建立猜測連結。

### 頂部安全區

- 共用 `.topbar` 的基礎樣式直接加入 `env(safe-area-inset-top, 0px)`，不再依賴 760px 媒體查詢。
- 手機與原生殼層保留原本較緊湊的 padding 覆寫，各層只計算一次安全區。
- 選擇題法條小窗的桌面／iPad 上緣同步加上安全區，避免小窗覆蓋加高後的導覽列。

## 驗收標準

- 「所得稅法第 34 條、第 51 條」會產生兩個可點擊連結，兩者皆指向所得稅法的正確條號。
- 「營利事業所得稅查核準則第 77 條」可點擊並開啟既有站內法條小窗。
- 點擊不呼叫 `window.open`、不更換頁面；按 ×、背景或 Escape 可關閉。
- `.topbar` 在不受 760px 限制的基礎規則中包含 `safe-area-inset-top`。
- iPad 橫向 1280×960 與直向 768×1024 的頂部導覽列不與系統狀態列重疊。
- 全部現有 Node 合約測試維持通過。
